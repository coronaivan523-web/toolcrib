RESUMEN MAESTRO - REPORTE TÉCNICO DE ARQUITECTURA
Fecha: 2026-01-21
Proyecto: ToolCrib (Sistema de Gestión de Pañol)

1. OBJETIVO DEL SOFTWARE
   El sistema tiene como objetivo gestionar el inventario, préstamos y requisiciones de herramientas y materiales (consumibles) en un entorno industrial ("Crib" o Pañol).
   Permite:
   - Controlar existencias de materiales (Stock actual, pendiente, mínimos).
   - Gestionar solicitudes de usuarios (Tickets) mediante un sistema de "Carrito" para múltiples ítems.
   - Automatizar el flujo de Requisiciones (Compras) con niveles de aprobación secuenciales (Solicitante -> Gerentes -> Compra).
   - Realizar Conteos Cíclicos (Auditorías de inventario).
   - Reportar problemas de calidad.

2. LISTA DE TABLAS DE BASE DE DATOS (Detectadas)
   - users (Supabase Auth - Gestión de identidad)
   - profiles (Extensiones de usuario: rol, número de empleado, avatar)
   - materials (Catálogo de ítems: SKU, descripción, stock, ubicación, imágenes)
   - tickets (Cabecera de solicitudes de material)

   - requisitions (Cabecera de solicitudes de compra/abastecimiento)

   - messages (Sistema de mensajería interna, tabla reciente)
   - cycle_counts (Auditorías de inventario - Refactorización reciente a V2)

3. REGLAS DE NEGOCIO PRINCIPALES
   A. Requisiciones (Compras):
      - Flujo estricto de estados: DRAFT -> UNDER_APPROVAL -> APPROVED_PRE_PURCHASE -> ORDERED -> RECEIVED.
      - Aprobación en cascada: Si un gerente rechaza, el estado cambia a REWORK_REQUIRED (Corrección).
      - Al reenviar una corrección, se reinician las aprobaciones futuras pero se mantiene el historial.
      - Uso de "Admin Client" en backend para bypass de RLS en flujos críticos.

   B. Tickets (Préstamos/Consumo):
      - Sistema de Carrito: Los usuarios agregan múltiples materiales antes de confirmar.
      - Validación de Stock: No se permite solicitar más de (Stock Actual - Stock Pendiente).
      - Datos de Trabajo: Se requiere especificar Planta, Área, Máquina y Proceso para cada ítem (Trazabilidad de costos).
      - Actualización en Tiempo Real: Uso de Supabase Realtime para que el pañolero vea solicitudes al instante.

   C. Seguridad y Roles:
      - Roles definidos: Admin, Supervisor, Toolroom Staff, User.
      - RLS (Row Level Security): Implementado en PostgreSQL para aislar datos, aunque frecuentemente bypasseado por el backend para gestión centralizada.
